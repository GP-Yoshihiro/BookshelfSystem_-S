# シリーズまとめ表示と発売日アラート 設計書

- 作成日: 2026-09-18
- 対象: README.md 機能要件C の再定義（利用者からの仕様変更）
- ブランチ: `feature/series-grouping`（C-1）/ 後続（C-2）
- 前提: PR #6 までがマージ済みであること

## 1. 変更の背景

当初 README は「カレンダー予約データ: ユーザーIDと書籍IDの紐付け」としており、
工程0で `calendar_reservations` を `books` への外部キー付きで作成した。

しかし利用者の意図は **ベルアラート方式**、すなわち

> 作品（シリーズ）を登録しておくと、新刊の発売日が自動で分かる

というものであり、かつ **発売日の通知と本棚は完全に独立**である。

`calendar_reservations` は `book_id` が必須のため、本棚に入っていない本を
カレンダーへ載せられない。したがってこの用途には使えない。

## 2. 目的

- 検索結果を作品（シリーズ）単位でまとめ、巻ごとに散らばらないようにする
- 欲しい巻だけを選んで本棚へ追加できるようにする
- 作品を登録しておくと、最新巻の発売日がカレンダーに載るようにする

## 3. スコープと分割

### C-1（本ブランチ）

- 検索結果のシリーズまとめ表示
- 巻を選んでの本棚追加
- セット商品・関連グッズの除外

### C-2（後続ブランチ）

- 発売日アラートの登録・解除
- 月別カレンダーと下部リスト
- 追跡中シリーズの新刊確認

### 含まないもの

- メール・プッシュ通知（SMTP 未整備のため。画面への反映までを実装する）
- 書籍の編集・削除
- `calendar_reservations` テーブルの削除（使わなくなるが、削除は別途判断する）

## 4. ★前提となる実データの調査結果★

実際の楽天APIレスポンスを調べ、以下を確認した。設計はこれに基づく。

### 4.1 `seriesName` は作品名ではない

```
薫る花は凛と咲く（24）  → seriesName = 講談社コミックス
魔法使いの夜　下        → seriesName = 星海社FICTIONS
```

`seriesName` はレーベル名であり、**グルーピングのキーには使えない**。
タイトルから巻数を剥がして作品名を得る必要がある。

### 4.2 巻数の表記が作品ごとに異なる

```
薫る花は凛と咲く（24）   全角カッコ
呪術廻戦 28             半角スペース区切り
呪術廻戦≡ 1            別作品。混同してはならない
```

単一の正規表現では足りず、複数パターンへ対応する。
`呪術廻戦≡` と `呪術廻戦` を同一視してはならない。

### 4.3 ノイズが混ざる

```
【全巻】 薫る花は凛と咲く 1-23巻セット
薫る花は凛と咲く　47都道府県ポストカードブック
```

## 5. 巻数の抽出

`parseVolume(title)` を純粋関数として実装する。

```ts
interface ParsedVolume { baseTitle: string; volume: number | null }
```

対応する表記（末尾一致のみ。途中の数字は巻数と見なさない）:

| 入力 | baseTitle | volume |
| --- | --- | --- |
| `薫る花は凛と咲く（24）` | `薫る花は凛と咲く` | 24 |
| `呪術廻戦 28` | `呪術廻戦` | 28 |
| `呪術廻戦≡ 1` | `呪術廻戦≡` | 1 |
| `タイトル(3)` | `タイトル` | 3 |
| `タイトル 第5巻` | `タイトル` | 5 |
| `ポストカードブック` | `ポストカードブック` | null |

**区切り文字を必須とする。** `ワンピース1` のように区切りのない数字は
巻数と見なさない。`ROOM No.1` のような題名を壊すおそれがあるため。
取りこぼしても「巻数なしの単独行」になるだけで、情報は失われない。

### 5.1 グルーピングのキー

`baseTitle` の前後空白を除去し、全角空白を半角へ正規化した文字列を使う。
大文字小文字は区別しない。

## 6. ノイズの除外

タイトルに以下の語を含む商品を、既定で検索結果から除外する。

```
セット / 全巻 / まとめ買い / 合本
```

**除外した件数は画面に表示し、押せば見られるようにする。** 除外規則が誤作動して
本当に欲しい本が消えたとき、利用者が気づけないのは害が大きいため。

```
他 3 件（セット商品など）を除外中  [表示する]
```

## 7. 検索結果の表示

### 7.1 まとめ行

同じ `baseTitle` の商品が 2 件以上ある場合、1 行にまとめる。

| 要素 | 内容 |
| --- | --- |
| 書影 | 最小巻のもの |
| 作品名 | `baseTitle` |
| 巻の情報 | `全 N 巻（最新 24 巻・2026/09/09 発売）` |
| ボタン | `発売日を通知` `巻を選んで追加` |

### 7.2 単独行

巻数を抽出できない商品、および同じ `baseTitle` が 1 件しかない商品は、
従来どおり 1 商品 1 行で表示する。ボタンは `本棚に追加` `購入済みとして追加`。

### 7.3 「最新巻」の判定

**巻数が最大のもの**を最新巻とする（利用者の選択）。発売日ではなく巻数を見るのは、
特装版や復刻版が発売日順で最新と誤判定されるのを避けるため。

### 7.4 取得件数について

まとめ表示には作品の全巻が必要になるため、1ページあたりの取得件数は
上限の 30 件のままとする。30 件を超える作品では一部の巻が欠けるが、
**欠けた巻があることを画面に明示しない**（総件数は表示する）。誤った
「全 N 巻」を断定するより、取得できた範囲で表示する方が誠実である。

表示は `全 N 巻` ではなく `取得 N 巻（最新 24 巻）` とし、断定を避ける。

## 8. 巻を選んでの追加

`巻を選んで追加` を押すと行が展開し、巻の一覧が出る。

- 各巻にチェックボックス。既定は未選択
- **既に本棚にある巻は「追加済み」と表示し、選択できない**
- 「選んだ巻を本棚に追加」「選んだ巻を購入済みとして追加」の2つのボタン
- 分類と連載中フラグは、まとめ行で一度だけ選ぶ（巻ごとに変えられるようにはしない）

一括追加は 1 つの Server Action で行い、成功件数と失敗件数を返す。
一意制約違反（既に本棚にある）は失敗ではなく「スキップ」として数える。

## 9. C-2: 発売日アラート

### 9.1 新テーブル `release_alerts`

`books` を一切参照しない。本棚と完全に独立させるため。

```sql
create table public.release_alerts (
  id                       uuid primary key default gen_random_uuid(),
  user_id                  uuid not null references public.profiles (id) on delete cascade,
  series_key               text not null,
  series_title             text not null,
  latest_volume            integer,
  latest_title             text not null,
  latest_isbn              text not null,
  latest_release_date      date,
  latest_release_date_text text,
  cover_image_url          text,
  checked_at               timestamptz not null default now(),
  created_at               timestamptz not null default now(),
  updated_at               timestamptz not null default now(),
  constraint release_alerts_unique unique (user_id, series_key)
);
```

RLS は全操作を `user_id = (select auth.uid())` に限定する。
既存テーブルと同じ書き方に揃える。

### 9.2 更新の契機

カレンダーを開いたときに、`checked_at` が 24 時間以上前のものだけ楽天へ
問い合わせて更新する。

**Server Component の描画中に更新してはならない。** 描画は副作用を持つべきでなく、
同じページを複数タブで開いたときに重複して走る。クライアント側の Client
Component が mount 時に Server Action を呼び、完了後に `router.refresh()` する。

### 9.3 カレンダー画面

- 月別グリッド（日〜土）。前月・翌月へ移動できる
- 発売日がある日にマーカーを出す
- 下部にスクロール可能なリスト。「これから発売」を先頭に、過去は下へ
- 各行から **アラートの解除**ができる（README の「カレンダー画面からは直接削除のみ」）
- 追加ボタンは `/search` へ遷移する（利用者の選択）

## 10. セキュリティ

- `release_alerts` の取得はキャッシュする。RLS を迂回する管理者クライアントを
  使うため、`userId` は必ず `supabase.auth.getUser()` 由来のものを渡す
  （工程Dの設計書 8.1 の規則）
- 楽天由来の文字列を `dangerouslySetInnerHTML` で描画しない
- 一括追加の Server Action では、`user_id` をフォームからではなく
  認証済みセッションから取得する

## 11. テスト戦略

純粋関数を切り出して Vitest で検証する。

| 対象 | 内容 |
| --- | --- |
| `parseVolume` | 全角/半角カッコ、スペース区切り、第N巻、区切りなし、`呪術廻戦≡` と `呪術廻戦` の非同一視 |
| `groupBySeries` | 2件以上でまとめ、1件は単独、最小巻と最大巻の特定、巻数なしの扱い |
| `isExcludedItem` | セット/全巻/まとめ買い/合本の検出、通常の巻を誤除外しないこと |
| `buildMonthGrid`（C-2） | 月初の曜日合わせ、月末の埋め、うるう年 |

楽天への実通信と Supabase への書き込みは自動テストの対象外とし、実ブラウザでの
確認とする。

## 12. 受け入れ基準

### C-1

1. 「薫る花は凛と咲く」で検索すると、巻がまとまって 1 行で表示される
2. その行に最新巻の巻数と発売日が出る
3. 「呪術廻戦」で検索したとき、`呪術廻戦≡` が別の行になる
4. セット商品と関連グッズが既定で除外され、除外件数が表示される
5. 除外件数を押すと、除外された商品が表示される
6. 巻数を抽出できない単独商品は、従来どおり 1 行で表示される
7. 「巻を選んで追加」で巻一覧が開き、選んだ巻だけが本棚に追加される
8. 既に本棚にある巻は「追加済み」と表示され、選択できない
9. 本棚は従来どおり 1 巻ずつ表示される
10. `typecheck` / `lint` / `build` / `test` がすべてエラーなく完了する

### C-2

11. 「発売日を通知」を押すとアラートが登録され、カレンダーに最新巻の発売日が載る
12. **アラートを登録しても本棚には何も追加されない**
13. カレンダーから同じ作品のアラートを解除できる
14. 24 時間以上前に確認したアラートは、カレンダーを開いたときに更新される
15. 別アカウントでログインすると、他人のアラートが見えない
16. Supabase Database Linter に新規の WARN が増えていない
