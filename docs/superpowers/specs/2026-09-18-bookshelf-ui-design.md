# 木製本棚UI 設計書

- 作成日: 2026-09-18
- 対象: README.md 「3. 機能要件詳細 B. 木製本棚UI（メイン画面）」
- ブランチ: `feature/bookshelf-ui`
- 前提: PR #4（楽天API連携・検索候補）までがマージ済みであること

## 1. 目的

登録済みの書籍を、木製の本棚に背表紙を並べた見た目で一覧表示する。
ソート・絞り込み・リアルタイム検索で目的の本へ辿り着けるようにし、
本を選ぶと詳細ページへ遷移できるようにする。

## 2. スコープ

### 含むもの

- 木製本棚UI（背表紙の生成、棚板、質感表現、レスポンシブ）
- プレビュー表示（表紙＋概要）。マウスとタッチで別々の操作系
- ソート（分類別 / 出版社別 / タイトル五十音順、昇順・降順）
- 絞り込み（分類、出版社、連載中、購入済み）
- リアルタイム検索（タイトル・著者・出版社）
- 書籍詳細ページ `/books/[id]`

### 含まないもの

- 書籍の編集・削除（誤登録の修正手段がないため、次の工程で早期に追加する）
- カレンダー（工程C）
- 本棚の並び順の手動入れ替え

## 3. 背表紙の生成

楽天ブックスAPIは表紙画像（`largeImageUrl`）は返すが、**背表紙の画像は提供しない**。
そのため背表紙は CSS で生成する。

| 要素 | 方針 |
| --- | --- |
| タイトル | `writing-mode: vertical-rl` による縦書き。日本語書籍に自然で、幅の狭い背表紙に収まる |
| 色 | ISBN から決定的に算出した色相を使う |
| 厚み | ISBN から決定的に算出し、数段階へ振り分ける |
| 質感 | 上下に内側の影、左右にハイライトを入れて丸みを表現する |

### 3.1 色を ISBN から決める理由

分類（コミック / ライトノベル等）で色を決める案もあるが、**同じ分類の本がすべて
同色になり見分けがつかない**。本棚は「あの赤い本」といった見た目の記憶で探せることに
価値があるため、本ごとに異なる色を割り当てる。

ISBN を元にするのは、**同じ本が常に同じ色になる**ためである。ランダムに決めると
再読み込みのたびに色が変わり、見た目の記憶が使えなくなる。DB にカラムを増やす必要も
ない。

実装は ISBN の文字コードから単純なハッシュを作り、色相（0-359）へ写像する。
彩度と明度は固定し、木目の背景から浮かない範囲に収める。

## 4. プレビュー表示

README の「概要（あらすじ・著者・発売日）のツールチップ」と、背表紙表示に伴う
「表紙が見えない」問題を、1つのパネルで解決する。

表示内容: 表紙画像、タイトル、著者、出版社、発売日、あらすじ、分類、連載中の別。

### 4.1 マウス操作（`hover: hover` の環境）

```
背表紙にホバー
  → 本が少し手前にせり出す
  → プレビューパネルを表示
クリック → 詳細ページへ遷移
```

キーボード操作では、フォーカスをホバーと同等に扱う。Tab で本を移動でき、
Enter で詳細ページへ遷移する。

### 4.2 タッチ操作（`hover: none` の環境）

タッチ端末にはホバーがないため、操作系を分ける。

```
本をタップ
  → その本がプレビュー中になり、パネルを表示
左右にスライド
  → 隣の本へプレビューが移動する（パネルは開いたまま）
プレビュー中の本をもう一度タップ
  → 詳細ページへ遷移
パネルの外をタップ
  → プレビューを閉じる
```

**判断の分かれ目**: スライドで別の本へ移った場合、その本が「プレビュー中」になる。
タップの挙動は常に「その本が今プレビュー中かどうか」で分岐する。つまり
プレビュー中でない本をタップすればプレビュー、プレビュー中の本をタップすれば遷移。

長押しでプレビューを出す案は採らない。長押しは OS の文脈メニューと競合しやすく、
利用者に学習を強いるため。

### 4.3 パネルの配置

画面幅で出し分ける。

| 環境 | 配置 |
| --- | --- |
| 広い画面 | 対象の本の近くにポップオーバーとして出す。画面端では内側へ寄せ、見切れないようにする |
| 狭い画面 | 画面下部に固定のシートとして出す。本の近くに出すと本棚が隠れ、スライドで隣へ移る操作の邪魔になるため |

## 5. レスポンシブ

棚板1枚あたりの表示冊数は固定しない。`grid-template-columns` の
`repeat(auto-fill, minmax(...))` により、画面幅に応じて自動的に増減させる。

棚板は本の列の下に敷き、木目と影で立体感を出す。

**実装上の注意**: 段数は画面幅で変わるため、棚板を段数ぶん手で並べることはできない。
グリッドの背景に、1行の高さと同じ周期の `repeating-linear-gradient` を敷き、
棚板が自動的に行数ぶん現れるようにする。行の高さを CSS 変数で持ち、
グリッドの行高と背景の周期の両方から参照して、ずれないようにする。

### 5.1 書籍が0冊のとき

棚板だけの空の本棚を描画し、「まだ本が登録されていません。『本を探す』から
追加してください。」という案内と `/search` への導線を出す。棚ごと消すと、
何をすればよいか分からない画面になるため。

## 6. ソート・絞り込み・検索

すべてブラウザ側で処理する。本棚の全件を一度取得し、以降の操作では通信しない。

README が求める「リアルタイム検索窓」を体感ゼロで実現でき、Supabase への
リクエストも増えないため。蔵書が数千冊に達するまでは実用上問題ない。

### 6.1 ソート

| 種別 | 内容 |
| --- | --- |
| 分類別 | 単行本 → シリーズ単行本 → ライトノベル → コミック の順 |
| 出版社別 | 出版社名の五十音順 |
| タイトル五十音順 | `title_kana` を優先し、無ければタイトル本体で比較する |

昇順・降順を切り替えられる。

**`title_kana` が無い場合の扱い**: 楽天が `titleKana` を返さない書籍がある。
カナが無いものを末尾へ固めると、探している本が見つからない。そのため
タイトル本体を `localeCompare('ja')` で比較するフォールバックとする。
並びは多少乱れるが、本が行方不明になるよりは良い。

### 6.2 絞り込み

分類、出版社、連載中、購入済みで絞り込む。複数条件は AND で結合する。

### 6.3 検索

タイトル・著者・出版社を対象に、部分一致でリアルタイムに絞り込む。

README は「タイトル、著者、関連タグ」と書いているが、本システムに tags の概念は
存在しない。分類と出版社がタグに相当するため、出版社を検索対象に含め、分類は
絞り込み側で扱うことで要件を満たす。

## 7. 書籍詳細ページ

`/books/[id]` で表示する。表紙、タイトル、著者、出版社、分類、連載中、購入済み、
発売日、あらすじ、楽天の商品ページへのリンクを表示する。

他人の書籍 ID を指定しても RLS により取得できないため、`notFound()` を返す。
「存在しない」と「他人のもの」を区別しない。区別すると、ID の総当たりで
他人の蔵書の存在を推測できてしまうため。

## 8. データ取得とキャッシュ

工程Dで実装した `getUserBooks(userId)` をそのまま使う。本棚一覧はキャッシュされ、
書籍の保存時に `revalidateTag` で無効化される。

詳細ページも `getUserBooks` の結果から該当 ID を引く。1冊のために別クエリを
投げるより、既にキャッシュされた一覧を使う方が通信が減るため。

**注意**: `getUserBooks` は RLS を迂回する管理者クライアントを使う。
`userId` は必ず `supabase.auth.getUser()` から取得したものを渡すこと
（工程Dの設計書 8.1 章の規則1）。詳細ページでも同じ規則が適用される。

## 9. セキュリティ

- 楽天由来の文字列（あらすじ等）を `dangerouslySetInnerHTML` で描画しない
- 表紙画像は `next.config.ts` の `remotePatterns` で許可済みホストのみ
- 他人の書籍 ID への直接アクセスは `notFound()` とし、存在を推測させない
- エラーオブジェクトをそのまま出力しない

## 10. 音声案内（CLAUDE.md 5章）

この工程では音声案内を追加しない。閲覧が中心で、README 5章が挙げる
「設定保存・書籍追加・カレンダー登録」のような主要処理が発生しないため。
編集・削除を追加する工程で改めて組み込む。

## 11. テスト戦略

純粋関数を切り出し、Vitest で検証する。

| 対象 | 内容 |
| --- | --- |
| `spineStyle` | 同じ ISBN が常に同じ色・厚みを返すこと。異なる20件の ISBN で色相が10種類以上に分かれること。厚みが定義した段階のいずれかに収まること |
| `sortBooks` | 3種のソート、昇順降順、`title_kana` 欠落時のフォールバック |
| `filterBooks` | 各絞り込み、複数条件の AND 結合 |
| `searchBooks` | タイトル・著者・出版社の部分一致、空文字で全件 |

DOM を伴うプレビューの挙動（ホバー・タップ・スライド）は、モックの維持コストが
実装の変更に見合わないため自動テストの対象外とし、実ブラウザでの確認とする。

## 12. 受け入れ基準

1. 本棚に登録済みの書籍が背表紙で並ぶ
2. 同じ本の背表紙の色が、再読み込みしても変わらない
3. 画面幅を狭めると1段あたりの冊数が減り、横スクロールが発生しない
4. マウスでホバーすると表紙と概要のパネルが出る
5. マウスでクリックすると詳細ページへ遷移する
6. タッチ端末で1回タップするとプレビューが出る
7. プレビュー中に左右へスライドすると隣の本へ移る
8. プレビュー中の本をもう一度タップすると詳細ページへ遷移する
9. Tab キーで本を移動でき、Enter で詳細ページへ遷移する
10. 分類別・出版社別・五十音順のソートが昇順降順とも動く
11. `title_kana` が無い書籍もソート結果から消えない
12. 分類・出版社・連載中・購入済みで絞り込める。複数条件が AND で効く
13. 検索窓へ入力すると通信なしで即座に絞り込まれる
14. 他人の書籍 ID を `/books/[id]` に指定すると 404 になる
15. 書籍が0冊のとき、空の本棚と `/search` への導線が表示される
16. 狭い画面ではプレビューが画面下部のシートとして出て、本棚を隠さない
17. `npm run typecheck` / `lint` / `build` / `test` がすべてエラーなく完了する
