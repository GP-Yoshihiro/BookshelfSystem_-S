# BookshelfSystem_-S
自分自身が購入している本の管理を行えるシステム。発売日の予定カレンダーなどの機能もあり。
役割と目的
あなたは優秀なフルスタックエンジニアです。
以下の仕様書に基づき、Next.js (App Router)、Supabase、Tailwind CSS、Vercelを用いた「購入済み書籍管理＆発売日カレンダーアプリケーション」を実装してください。
なお、Supabaseのデータベーススキーマ（テーブル構成・カラム定義・リレーション）については、要件を満たす最適な設計をあなたが考えて定義・構築してください。
システム仕様書
1. 技術スタック
フロントエンド / フレームワーク: Next.js (App Router, TypeScript)
スタイル / アニメーション: Tailwind CSS, Framer Motion
データベース / 認証: Supabase (PostgreSQL, Supabase Auth)
キャッシュ戦略: Next.js Server Cache (Data Cache / ISR, unstable_cache, revalidateTag), React cache()
外部API: 楽天ブックス書籍検索API
デプロイ環境: Vercel
2. データベースの役割と必要な管理データ概要
システム構築に必要なデータ構造（テーブル・カラム・RLS等のセキュリティ設計）は、以下の要素を網羅するようにあなたが最適化して構築してください。
ユーザー情報と権限管理: ユーザーのロール（管理者・一般）や拡張プロフィール
招待コード管理: 発行コード、作成者、使用状況（使用済みフラグ・使用者ID）
書籍データ（本棚管理）: ISBN、タイトル、著者、出版社、分類（単行本・シリーズ単行本・ライトノベル・コミック）、連載中フラグ（シリーズ・ラノベ・コミック用）、表紙画像URL、概要、購入済みフラグ、最新巻発売日
カレンダー予約データ: ユーザーIDと書籍IDの紐付け、予約済みの発売予定日
3. 機能要件詳細
A. 認証 & 招待コード機能
初回登録特例: DBにユーザーが1人も存在しない場合（1人目のユーザー作成時）のみ、招待コード無しでサインアップ可能。2人目以降は招待コードの検証を必須とする。
再認証ダイアログ: 招待コードの発行・コピー・詳細閲覧時には、セキュリティ保護のためアカウントの再パスワード入力を要求し、認証成功時のみ処理を実行する。
B. 木製本棚UI（メイン画面）
リアルな質感表現: 木目のテクスチャや立体感（シェード・シャドウ）を持つ本棚UI。レスポンシブ対応でスマホ〜PCの画面幅に合わせて棚幅や表示冊数を自動調整。
カード操作: 本にカーソルを合わせると概要（あらすじ・著者・発売日）を表示する吹き出し（Tooltip）を出現させる。クリック/タップで詳細ページへ遷移。
ソート & フィルター & 検索:
ソート: 昇順/降順、デフォルト（分類別、出版社別、タイトル五十音順）
絞り込み: 分類、出版社、連載中フラグなどのタグ
検索: リアルタイム検索窓（タイトル、著者、関連タグ）
C. 発売日予約カレンダー
独自カレンダーUI: 月別カレンダーおよびその下部にスクロール可能なリスト形式で最新発売日予定を表示。
追加・削除の動線:
カレンダー上の「追加ボタン」を押すと本一覧ページへ遷移。
本一覧ページからカレンダーへの追加/削除が可能。
カレンダー画面からは直接削除のみが可能。
D. 外部API連携 & キャッシュ
データ取得: 楽天ブックス書籍検索APIからタイトル・著者・出版社・分類・連載状態・最新巻発売日・表紙画像を取得。購入処理を行うとSupabaseへ保存。
負荷軽減（キャッシュ）: Supabaseへの過剰リクエストを防ぐため、Next.jsのunstable_cacheやrevalidateTagを用いたサーバーキャッシュを構築する。
